# UI 性能优化与验证（2026-11-01—02）

本轮在原生 Hash SPA 中优化共享外壳与 Liquid Glass 材质，没有增加运行依赖或构建步骤。保留浅色网格、透明填色、边缘高光和多层阴影，同时验看 Soft UI。

## 渲染改动

- 静态卡片、导航、按钮、表单以及二维码、压缩、拼豆和游戏外围面板，不再逐个采样背景。用内阴影绘制玻璃边缘，渐变直接绘制反光，移除作用于整个控件及其文字的亮度滤镜。
- 对外层卡片、页头及主要工具面板保留单个合成缓存，内部按钮和表单共用这个缓存。对照中直接去掉滤镜曾使滚动反复绘制边缘阴影，外层缓存避免了这一退化；没有把每个小控件都提升为独立层。
- 玻璃大面板的公共阴影由六层简化为四层，小控件由六层简化为三层。播放器主面板保留 10px、收起状态保留 8px 的背景模糊；助手入口保留 10px，展开后使用较实的透明底色。浮层、菜单、Toast 仍按需保留局部模糊。
- 播放器的收起播放按钮复用外层材质，不再重复模糊；闲置的拖入提示使用 `visibility: hidden`，避免透明但仍有布局框的滤镜层。
- 移除三个已经不可见、却仍循环动画并声明 `will-change` 的旧背景光球。播放器和助手不再永久声明整组尺寸属性的 `will-change`；助手入口提示点播放三轮后停止。
- 魔方贴纸的渐变反光和背后的柔光不再额外做模糊。静止时停止动画帧；背景漂浮限制为最多 30 次/秒，视角旋转和惯性按经过时间计算。拖拽、转面及聚散过程仍正常刷新。
- 页面隐藏或进入页面缓存时，外壳暂停 CSS 动画，魔方取消动画帧和待机定时器；返回时扣除隐藏时间，延续聚散进度。系统开启减少动态效果后，魔方停止自动散开、漂浮与待机旋转，手动操作仍可用。页面卸载通过原有 AbortController 清理新增监听。
- 修复检查中发现的图片压缩页窄屏溢出：Liquid Glass 的子元素叠层规则曾把透明文件输入框改成正常布局，现恢复绝对定位，仍覆盖上传区域。
- 同步 Lens 预览的外壳副本，继续遵循它与正式外壳逻辑一致、存储隔离的约定。

## 浏览器实测

使用本地 Express 服务和内置浏览器，外层视口 1440 × 1000，测试页面放在 1280 × 800 的 iframe 中。每页加载后等待 4 秒，再按相同轨迹连续滚动 6 秒。专用对照服务在同一个来源下交替提供修改前的 Git 文件和当前文件；测试框始终完整位于视口内，并在测量前检查位置，结果区放在它下方。

下表对有布局框、且未设置 `display: none` 或 `visibility: hidden` 的节点统计计算样式，包含透明节点；装饰层统计 `::before` / `::after`，循环动画统计实际仍在运行的 CSS 动画。

| 页面 | 背景模糊层：前 → 后 | 元素滤镜：前 → 后 | 模糊装饰层：前 → 后 | 运行中的 CSS 动画：前 → 后 |
| --- | ---: | ---: | ---: | ---: |
| 工具箱 | 26 → 2 | 25 → 0 | 49 → 0 | 6 → 0 |
| 二维码制作 | 46 → 2 | 44 → 0 | 57 → 0 | 6 → 0 |
| 首页魔方 | 15 → 2 | 13 → 0 | 78 → 0 | 8 → 2 |

剩余两个背景模糊节点是浮动播放器与收起的助手入口。首页保留魔方柔光与访问提示的 CSS 动画，JavaScript 背景漂浮单独按 30 次/秒限制。

这些是 CSS 滤镜节点和动画数量，不是浏览器内部实际分配的纹理数量，也不代表 CPU / GPU 占用或帧率同比降低。最终对照的平均帧间隔分别为：工具箱 3.58 → 3.57ms、二维码 3.57 → 3.57ms、首页 3.63 → 3.59ms，六组的第 95 百分位均为 3.7ms；均无超过 25ms 的帧或超过 50ms 的主线程长任务。这台机器原本已接近约 280Hz 的调度水平，本轮保持了它的滚动表现，不据此宣称固定的帧率提升百分比。

## 生效与验证边界

这些修改在本地工作区完成，尚未推送或部署。Express 会按内容生成 CSS / JS 版本地址；上线时同步修改的前端文件和 Lens 外壳副本即可，服务器端功能没有改变。普通静态托管仍需按 README 管理资源版本和缓存。

未测试所有游戏的完整游玩、实际低配置手机的 GPU 占用、不同显卡的耗电或正式站点的 CDN 行为。静态材质优化、动画预算和后台清理已验证，实际收益取决于设备、分辨率及打开的页面内容。
